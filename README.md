# 小白出行规划管家（Travel Planner Skill）

一个面向旅行小白的 Codex Skill，把“我想出去玩”逐步整理成一份可核验、可预订、可执行，并且遇到变化时有备选方案的旅行计划。

它不只是罗列景点，而是会先了解同行者、日期、预算、交通和体力，再从大到小完成路线、住宿、用车、预约、预算、风险与出发前检查。

## 它能解决什么问题

旅行攻略最麻烦的部分，通常不是找不到景点，而是信息太多、彼此冲突，而且容易遗漏真正影响体验的细节。

这个 Skill 主要解决以下问题：

- 不知道应该先订机票、酒店，还是先排行程。
- 路线看起来很丰富，实际一直赶路、走回头路或频繁换酒店。
- 只看票面价格，漏算接驳、行李、停车、保险、异地还车等成本。
- 不知道住景区、住县城还是住交通枢纽更合适。
- 忽略儿童、老人、晕车、高海拔、无障碍或慢性病需求。
- 使用了过期的票价、道路、天气、预约或签证信息。
- 临近出发才发现景区没预约、道路管制或订单不能取消。
- 攻略很长，真正到现场时却找不到当天最重要的信息。

## 核心能力

### 1. 从模糊想法开始规划

当信息不足时，Skill 会优先询问最多 8 个真正影响日期、路线、预算或安全的问题，而不是立刻生成一张看起来很满的行程表。

如果用户不想逐项回答，它会采用保守假设，先输出一版可以继续讨论的路线骨架。

### 2. 先判断行程是否成立

在搜索大量酒店和景点以前，会先检查：

- 总天数与住宿晚数是否匹配。
- 是从家一路自驾，还是抵达目的地后租车。
- 全程移动时间、最长单日移动和真正可游玩的时间。
- 预算是目标金额还是绝对上限。
- 计入 10%～20% 机动金后是否仍在预算内。

最后给出 `可行`、`偏紧` 或 `不建议照此执行` 的明确判断。

### 3. 由粗到细生成可执行路线

先确定进出城市与路线方向，再逐步补充：

- 每天的起点、终点和核心体验。
- 预计移动时间和行程强度。
- 住宿区域及是否值得连住。
- 景区预约渠道、开放时间与证件要求。
- 自驾、租车、公共交通、包车或小团的选择。
- 饮食、补给、厕所、洗衣、网络、支付和行李。
- 天气、道路、预约失败和同行者疲劳时的 Plan B。

### 4. 处理动态信息，降低“攻略幻觉”

票价、房价、天气、道路、签证、景区规则、营业时间和预约库存都可能变化。

Skill 要求在具备联网能力时优先核验近期官方信息，并标注来源与查询日期；无法验证时必须说明，而不是补造一个确定答案。

计划中的信息统一使用以下状态：

| 状态 | 含义 |
|---|---|
| `已确认` | 用户已经提供订单、官方确认或明确决定 |
| `当前规划` | 推荐方案，但尚未最终预订或核验 |
| `待核验` | 价格、天气、库存、道路或政策仍可能变化 |
| `备选` | 主方案不可用时启用 |

### 5. 支持特殊旅行场景

内置参考规则覆盖：

- 亲子旅行
- 老人或行动不便者
- 晕车、晕船等乘车不适
- 孕期、慢性病或医疗需求
- 高海拔旅行
- 自驾与租车
- 偏远地区和季节性道路
- 国际旅行
- 徒步、露营和户外活动
- 独自旅行
- 宠物同行

### 6. 临近出发极速模式

距离出发不足 7 天时，不再按普通节奏反复收集信息，而是：

- 只追问 1～3 个阻塞执行或影响安全的问题。
- 先列出现在立刻要做的 3 件事。
- 给出最晚决策时间和可以先锁定的可退订单。
- 准备预约失败、天气变化和预算超支后的即时替代。

### 7. 输出手机每日行程卡

路线和订单确认后，可以将每天的关键信息压缩成适合保存在手机相册中的卡片文案，包括：

- 当日路线和出发时间
- 预计移动时长
- 一个核心体验
- 预约状态
- 补给和住宿
- 穿着提醒
- 最大风险与 Plan B

## 安装

使用前需要一个支持本地 Skills 的 Codex 环境。Skill 本身没有第三方代码依赖；查询票价、天气、道路和预约等动态信息时，需要为 Codex 提供联网能力。

### 方法一：克隆仓库

```bash
git clone https://github.com/ColourCloudSky/travel-planner-skill.git
mkdir -p ~/.codex/skills
cp -R travel-planner-skill/travel-planner ~/.codex/skills/travel-planner
```

如果已经安装过旧版本，请先把旧目录移动到备份位置，再复制新版本，避免新旧文件混合。

### 方法二：下载 ZIP

1. 在 GitHub 仓库页面选择 `Code → Download ZIP`。
2. 解压下载文件。
3. 将其中的 `travel-planner` 文件夹复制到 Codex Skills 目录：
   - macOS / Linux：`~/.codex/skills/travel-planner`
   - Windows：`%USERPROFILE%\.codex\skills\travel-planner`
4. 新建一个 Codex 任务，让 Skill 重新被发现。

安装完成后的关键路径应为：

```text
~/.codex/skills/travel-planner/SKILL.md
```

不要多嵌套一层目录，例如 `travel-planner/travel-planner/SKILL.md`。

如果你的环境显式设置了 `CODEX_HOME`，请改用 `$CODEX_HOME/skills/travel-planner`，而不是默认的 `~/.codex/skills/travel-planner`。

## 快速开始

安装后，在新的 Codex 任务中输入：

```text
使用 $travel-planner 帮我从零规划一次旅行。
```

也可以直接描述需求，Skill 会根据旅行规划、自由行、自驾、亲子游、酒店选择、预算控制、出发前检查等语义自动触发。

例如：

```text
使用 $travel-planner，帮我规划一次8月份的新疆亲子自驾游。
2位成人、1名7岁儿童、8天、总预算2万元。
```

## 建议提供的信息

不需要一次准备齐全，但以下信息越完整，第一版方案越准确：

```text
出发地：
目的地或想看的景观：
准确日期与弹性：
总天数与晚数：
同行人数和年龄：
目标预算与绝对上限：
预算是否包含往返大交通：
偏好的交通方式：
驾驶人数与每天可接受的移动时间：
住宿预算和位置偏好：
必去、可放弃、不喜欢的项目：
儿童、老人、晕车、饮食或健康需求：
```

如果已经预订了机票、酒店或租车，可以直接上传截图。建议保留日期、价格、房型、航班时间、车型和取消政策，并遮挡姓名、手机号、证件号、订单号、二维码及确认码。

## 常用使用方式

### 从零做一份旅行计划

```text
使用 $travel-planner，帮我规划一次从上海出发的6天日本自由行。
2位成人，预算2万元，第一次出国，希望交通简单、少换酒店。
```

### 根据已有订单继续规划

```text
使用 $travel-planner。机票和前两晚酒店已经订好，截图如下。
请围绕这些已确认订单继续规划，不要从头推荐航班和酒店。
```

### 审查现有攻略

```text
使用 $travel-planner 检查这份行程有没有回头路、连续高强度、预算遗漏、预约风险和赶不上返程的问题。
```

### 比较酒店或租车方案

```text
使用 $travel-planner，根据我的逐日路线比较这几家酒店。
不要只比较房价，还要考虑绕路、停车、早餐、取消规则和第二天出发成本。
```

```text
使用 $travel-planner，根据我的自驾路线比较截图中的车型。
重点考虑真实结算价、保险、儿童座椅、行李空间、油耗、山路舒适性和取还车网点。
```

### 临近出发检查

```text
使用 $travel-planner。我5天后出发，请进入临时出发模式，先告诉我现在立刻要做的3件事，再检查天气、道路、预约、订单和行李。
```

### 生成手机相册版

```text
使用 $travel-planner，把已经确认的逐日行程压缩成手机每日卡片文案。每张只保留当天真正需要的信息。
```

## 默认输出内容

根据任务阶段，Skill 会选择性输出：

1. 一页结论与可行性判断
2. 已确认信息和当前假设
3. 推荐方案与至多两个备选
4. 逐日路线和单日执行页
5. 交通、住宿和景区建议
6. 预算表与超支删减顺序
7. 按日期排列的预订和核验清单
8. 行李、健康与安全提醒
9. 天气、道路或预约失败后的 Plan B
10. 出发前 72 小时和 24 小时检查
11. 手机每日行程卡片文案

Skill 不会为了模板完整而把所有清单原样倾倒给用户。简单问题会优先给精简版，需要执行或留档时再展开完整版。

```text
travel-planner-skill/
├── README.md
└── travel-planner/

    └── references/
```

- `SKILL.md`：核心工作流、状态规则、安全边界和质量闸门。
- `planning-checklist.md`：交通、住宿、景区、预算、证件、天气等完整检查清单。
- `special-scenarios.md`：亲子、老人、晕车、高海拔、自驾、境外等特殊场景规则。

- `agents/openai.yaml`：Codex Skill 列表中的显示名称、简介和默认提示词。

## 安全与真实性边界

- 未经用户明确授权，不购买、不预订、不付款、不提交证件，也不对外发送信息。
- 动态价格只代表查询当时，不声称找到了永久最低价。
- 道路、天气、签证、预约和开放规则必须以近期官方信息为准。
- 直播和社交媒体可用于观察现场感，不能单独证明未来状态。
- 涉及医疗、签证、法律或高风险活动时，提示向医生或主管机构确认。
- 不把氧气、药物、某种车型或任何单一装备描述成安全保证。
- 不鼓励疲劳驾驶、夜间山路、危险停车、非正规穿越或绕过管制。

## 已完成的测试

当前版本通过了 Skill 结构校验，并使用以下场景进行前向测试：

- 深圳出发的新疆亲子自驾
- 带70岁父母的东京低步数自由行
- 临近出发且容易晕车的张家界旅行

测试重点包括可行性判断、问题数量、预算范围、动态信息标记、老人和儿童需求、临时出发模式、医疗边界及不代订原则。

## 使用限制

- Skill 能显著减少遗漏，但不能消除天气、交通、健康和临时管制风险。
- 航班、酒店、租车和景区库存仍需在真实预订页面确认。
- 地图预计时间必须加入休息、停车、排队、加油或充电及山区低速余量。
- 最终决定和订单操作始终由旅行者本人完成。

## 反馈与改进

如果遇到 Skill 没有覆盖的旅行场景，或发现某项工作流容易产生误解，可以在 GitHub Issues 中提供：

- 你的原始旅行需求
- Skill 的实际输出
- 你认为遗漏或不够好执行的部分
- 已遮挡个人信息的相关截图

请勿在 Issue 中上传身份证、护照、手机号、订单号、确认码、二维码或支付信息。
